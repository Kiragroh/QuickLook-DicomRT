# macOS feature completion and performance plan

Author: Max Grohmann / implementation agent
Date: 2026-11-03
Status: independent EGM source and readiness reviews completed; findings incorporated. Implementation, testing, installation and push authorized by the user.

## Goal and acceptance boundary

Bring the current macOS port closer to the existing Windows viewer, preserving the original compact layout, RT association rules and algorithms. Close the remaining user-visible feature gaps identified by a source audit, then build, test on the three independently supplied original cases, install and push the macos-preview branch. Do not claim universal feature parity from three cases. Do not publish private data, source names, identifiers, UIDs or paths. Source DICOM files remain read-only. Unknown device identity, registration and jaw coordinates stay unknown.

## Baseline and constraints

The current branch is 3bd0be5. The Mac uses original Core and Rt algorithms and linked RenderScene, ReformatContours, MlcTimeline, ThreeDGeometry, RtSliceBounds, BeamMetersetInfo and PlanDicomExport. Its UI is local WebKit, hosted by the same PreviewController in the standalone app and sandboxed Quick Look extension. Keep that architecture and use no new runtime network dependencies. User-confirmed Standard/STX palettes and D0.035 cm³ normalization take precedence over older Windows percentage defaults.

Known gaps requiring verification against Windows source:

- Mac holds one active DoseGrid and StructureSet. Windows can display multiple plan-associated dose overlays and has a separate DVH dose choice. Exact opened RTDOSE must stay selected, and ambiguous associations must not be guessed.
- Mac Select reloads the entire image stack even when unchanged. Native image scrolling decodes from disk again. Rendering and Base64 conversion occupy the session gate; response JSON serialization occurs after releasing it, but still uses the native serial queue. Background surface, contour and DRR work can continue after a view change.
- Windows has multiple-isocenter and dose-maximum navigation, per-view orientation indicators, field selection including neutral state, movable MLC orientation context and keyboard interactions. Compare these with current Mac controls before claiming completion.
- Mac detailed CSV currently omits uncomputed enabled structures rather than recording NotCalculated. Labels must follow the selected description/name mode.
- Finder currently has a read-only library allowance and bookmarks; arbitrary-folder access still depends on the OS sandbox. Improve the contextual local-access flow and shared app/preview state without granting broad filesystem access or pretending the sandbox does not exist.

## Design plan

Archetype: Finder preview and single-window inspection document, with original RT sidebar and optional tag inspector. Information architecture: RT selection, Structures/Doses tabs; Image, MLC, DVH and 3D workspaces. No new navigation hierarchy. Feeling: quick inspection of the original data.

Command map: retain Windows actions with Command replacing Control where appropriate. Image modes Command 1–6 follow Windows order Native/Axial/Coronal/Sagittal/2×2/3D. Command I navigates isocenters; Command Shift S exports; Command F searches tags; Home fits; Option I/M/D/V switches workspaces. Native File Open, Close, Quit and Settings use standard macOS shortcuts.

UX: Dose visibility is inline in Doses; active DVH dose is chosen above the existing chart. ISO with multiple coordinates opens a small anchored choice; dose maximum is an action beside the dose list. Neutral field is a selection in existing field controls. Movable/resizable MLC orientation context stays within the MLC tile. Missing coordinates or unmapped overlays show a reason and remain unavailable. Exports record every requested ROI status in detailed CSV. Progress reports actual jobs; stale jobs cannot overwrite the new context.

## Resolved contracts after independent review

### Selection and dose protocol

- Retain legacy `plan`, `structure`, `dose`, `series` integer selectors and the ambiguity behavior of `dose` (a unique or exact explicit source only). Add `activeDoses` containing all explicitly referenced plan doses, or the exact standalone dose, or one uniquely compatible standalone-structure dose. Add `dvhDose` as a separate explicit display choice, defaulting to the first associated dose as Windows does; it does not change the plan/structure or visible overlays. Model lists expose opaque instance keys for restoring UI state across staged discovery.
- Plan selection uses its exact referenced structure and all dose instances whose single referenced plan matches. Opening an exact dose preserves it through discovery even among alternatives; structures come from its referenced plan, otherwise all registered candidate structure sets. Opening a standalone structure automatically chooses a dose only if exactly one compatible candidate exists. No compatible frame is invented. Multiple plan/image matches require a visible plan choice.
- `render.overlays` is an ordered array of `{id, visible, reference}` for active doses. Validate every id against activeDoses; absent list preserves the legacy single-dose render contract. Add optional `DoseOverlay.Normalization`, default zero, and copy it in RenderScene.Snapshot; default shared Windows behavior stays unchanged. Physical and relative grids are never added together; absolute isodoses require visible physical Gy grids. Relative overlays use their own display reference; a pending/unavailable physical reference disables that overlay until known or manually entered.
- `dvh`, `doseReference`, `mesh(kind=dose)`, and `export(kind=csv)` accept `doseId`; absent id uses the current unique/first display dose. Cache keys include dose identity plus ROI/context/mesh level as applicable. Source prescription and body contour belong to that dose's referenced plan, or compatible standalone structures; sum has no synthetic prescription. Each overlay has per-dose reference/levels/manual-reference state in the frontend. DVH changes preserve ROI visibility, zoom, image, field cursor and isodose controls. Sum uses its one synthetic grid and all included structures; changing context clears sum state.

### Additional source-confirmed gaps to implement

- Tag-source picker exposes current image, opened object and all catalog RT/REG objects via validated opaque catalog indices. Opening an RT object defaults its tags to that object, not its associated CT.
- Navigation includes all distinct mapped control-point isocenters, registered dose maximum, original shortcut ordering and input guards, and image-workspace field controls. Add a fast `fields` request accepting rendered-plane parameters, updating only field geometry on an unchanged raster during CP movement. Neutral selection draws treatment tracks without highlight. Entire-plan playback crosses field boundaries without interpolating between beams; add restart and beam-end timeline marks.
- MLC orientation card includes a cached axial CT at the current CP isocenter, synchronized field arrangement when Fields is on, and LINAC orientation. Move/resize/reset acts on both. CP updates reuse the CT slice if its source, iso and window are unchanged. Expose missing-volume status. Per-image orientation badges follow original LPS geometry and selected avatar. DRR contrast includes Auto and changes cached ray data without tracing new rays.
- Dedicated DVH PNG contains an independent chart with equal-opacity enabled curves, legend, metrics, statuses and approximation/partial-coverage notice. Detailed CSV records NotCalculated rows and uses original ROI Name as Windows does; description modes affect the rendered PNG/legend. Simple CSV contains calculated curves only, matching Windows.

Suppress preparation for the partial model. Final discovery preserves any user-changed view, focus/window/zoom and structure visibility using instance keys. Partial status explicitly says context is loading; no missing-dose conclusion before completion.

### Scheduling, cache and correctness policy

- Document generation changes close the engine session and cancel its lifetime token. Context generation changes on plan/structure/series/sum/discovery changes. Projection generation changes on outline/filter/tone/view changes. Render requests use immutable session snapshots, including fusion and selected-dose arrays. Native slice entry/pixels are chosen from the snapshot; metadata source state is changed only by explicit navigation, not background renders. Queue at most one latest interactive render; stale responses cannot update image geometry, overlays, status or progress.
- Use named worker job groups with monotonic revision and linked cancellation token for projection/preparation work. Advancing a group cancels running tokens; requests with older revisions are rejected before execution. Completion handlers compare document, context and group revisions. DVH jobs are context-dependent rather than view-dependent. Cancelled jobs do not populate caches or overwrite status. Frontend pending promises receive a cancelled result rather than being abandoned.
- Keep one active 512 MiB maximum volume plus one explicitly selected fusion volume (existing original cap), no hidden multi-volume cache. Cache decoded native planes FIFO, at most 9 entries/32 MiB; derive planes from loaded volume without rereading source. Skip oversize entries. Worker DRR ray cache remains at most 64 MiB/256 entries; projected outlines 512 entries; ROI surface cache 8 million vertices/256 entries; serialized meshes 10 million triangles/96 entries. Cache keys include context and source geometry; immutable mapped contours are per-context. Frontend prepared projection frames use FIFO 64 MiB/24,000 entries; decoded image pixels stay with currently visible tiles, not a growing raster cache. GPU surfaces retain the existing 8-million-triangle scene cap. Document close disposes GPU objects and clears buffers. Shared caches use synchronized bounded insertion/eviction; generation keys prevent reuse across contexts.
- Coalesce 3D appearance updates to one animation frame. Reuse LINAC/character meshes across CPs, updating rotations only; rebuild only for model/character/patient-position changes. Reuse slice textures and release them on reset/dispose. Do not reduce final resolution or alter dose/DRR numerical algorithms to obtain speed.

## Implementation adjustments

The CLI Program.cs now applies the same snapshot/job-generation contract as the native bridge, so cancellation tests cover both entry points. The Display math harness verifies byte-for-byte serial/parallel raster equality. Renderer row-range rejection is conservative: only rows where no cell can cross an isodose are skipped; final contour geometry is unchanged. Parallel rows are used for full/refinement rasters, retaining serial scheduling for smaller interaction rasters.

Source review of the original playback code confirmed 80 ms anchored fractional CP steps and separate progressive recorded-CP playback. The Mac now uses those same step rules and prepares contours before DRRs when that preference is enabled. Cancelled shared Lazy ROI mesh results must be removed and retried for a current caller; otherwise cancelled projection work can poison later 3D requests.

Additional user-authorized documentation: README.md; docs/windows-design-improvements.md; docs/assets/view-icons/{axial,coronal,sagittal,quad,3d}.svg. Coronal and sagittal plane vectors were made geometrically distinct. Program.cs and Mac/Tests/Display/Program.cs are added to the source/test file boundary.

Early interactive raster samples showed tiered-JIT warmup variance, while full-resolution rendering and CP/selection improved. The macOS worker uses optimized compilation from its first execution (`TieredCompilation=false` in Worker.csproj), measured against the same old worker with alternating request order. This avoids reporting warm 512-pixel improvements while accepting a regression in early 256-pixel frames. This runtime setting affects only the Mac worker, not Windows.

Final corrections also include source-dose/physical-threshold keys for 3D isodoses; conversion of custom level/color/visibility state across percent/Gy; explicit current crosshair coordinates on image-series selection after snapshot rendering; and document-generation guards around asynchronous native panels. Native acceptance covers all three normalization/navigation cases. Original-byte ZIP/CSV acceptance is implemented in Mac/Tests/private_exports.py.
